课程AD 诊断作业

《科学人工智能》课程作业 · 必做

用 Vibe Coding，构建一个会读脑 MRI 的诊断 Agent

我们给你 150 例脑 MRI，外加每位受试者的年龄与性别。没有认知量表，没有 PET。请用任何你顺手的 AI 编程工具，搭建一个可运行的智能体系统，对每一例给出 CN / MCI / AD 三分类判断。本专题提供完整数据集、两版示例 Agent 程序，以及我们自己从 34.7% 做到 56.0% 的全部 vibe coding 思路。

任务目标

开发一个基于智能体（Agent）的阿尔茨海默病辅助诊断系统。系统接收一例脑部 MRI 及受试者基本信息，输出 CN（认知正常）/ MCI（轻度认知障碍）/ AD（阿尔茨海默病）三分类结论。

输入限定

  • 允许使用的输入仅限三项：脑部 MRI（NIfTI 格式，.nii / .nii.gz）、年龄、性别。
  • 不得使用认知量表（MMSE、MoCA 等）、PET、脑脊液、基因型等任何其他信息作为模型输入。
  • 对 MRI 做任何形式的预处理、分割、量化均不受限制（如 FreeSurfer、SynthSeg、FSL 等）。

输出要求

  • 对每一例输入，系统必须给出 AD / MCI / CN 三标签之一的明确结论；鼓励同时输出判断依据与置信度，但不作硬性要求。
  • 系统必须支持上传一例新的脑 MRI 文件并完成推理，而不只是批量跑通给定数据。

评测要求

  • 使用本专题提供的 150 例数据集（CN / MCI / AD 各 50 例）在你自己的系统上完成全量评测，计算并如实报告三分类正确率。
  • 正确率不设及格线，尽量做高即可；评分同时考察系统完整性、方法合理性与评测诚实度。
  • 推理失败、超时或拒答的样例应计入分母，不得从统计中剔除。

完成形式

  • Vibe coding 工具不限（Claude Code、Cursor、Copilot 或任何你喜欢的工具），技术栈不限，完成形式不限。
  • 系统必须可运行：Windows 程序、Linux 程序、Web 应用均可；Web 应用部署在公网或校园网均可。

提交物（建议项，请按课程实际要求调整）

  1. 可运行的程序（或可访问的 Web 地址）及运行说明；
  2. 150 例评测结果明细与总体正确率；
  3. 简要技术说明（系统架构、Agent 设计、使用的工具链）；
  4. Vibe coding 过程记录（关键提示词、迭代过程，鼓励附踩坑记录）。

认识阿尔茨海默病

你的对手是谁

它是什么

阿尔茨海默病（Alzheimer's Disease, AD）是最常见的痴呆类型，约占所有痴呆病例的六到七成。它是一种进行性神经退行性疾病：β 淀粉样蛋白斑块与 tau 蛋白缠结在脑内逐渐累积，神经元不可逆地丢失，大脑随之萎缩。其中海马与内侧颞叶往往最早、最明显地受累，这也是为什么“记不住最近的事”常常是第一个信号。

医学上通常把认知状态看作一条谱系：CN（认知正常）→ MCI（轻度认知障碍，记忆或认知已有客观下降但尚能独立生活，每年约有 10%–15% 进展为痴呆）→ AD（痴呆阶段）。你在这份作业里要做的三分类，对应的正是这条谱系上的三个阶段。

医学上如何诊断

真实的临床诊断是一套组合拳：医生会详细询问病史，做神经心理量表（如 MMSE、MoCA）评估认知功能，再借助影像与生物标志物寻找客观证据。结构 MRI 观察脑萎缩模式，FDG-PET 观察脑代谢，淀粉样蛋白/tau PET 与脑脊液检测直接探查病理蛋白，近年快速发展的血液标志物（如 p-tau217）也开始进入临床。现代诊断框架（如 NIA-AA 的 ATN 体系）正是围绕“淀粉样蛋白、tau、神经退行性变”三类证据构建的。而在这些手段出现之前，AD 的确诊金标准长期只有一个：尸检病理。

现有诊断的难点与局限

每种手段都有代价。PET 昂贵且设备稀缺，多数基层医院无法开展；脑脊液检测需要腰椎穿刺，属于有创检查；量表结果受教育水平、语言、情绪甚至当天状态影响，主观性不小；而最难的部分在疾病早期。MCI 与正常衰老的边界本就模糊，不同医生之间也常有分歧。诊断资源的不均衡，使大量患者确诊时已错过最佳干预窗口。

纯 MRI 诊断：可行吗？

结构 MRI 是所有影像手段中最普及、最便宜、完全无创的一种，而 AD 在 MRI 上确实留有指纹：海马萎缩、内侧颞叶变薄、脑室扩大、顶叶萎缩，都有明确的诊断价值。临床上本来就有专门的视觉评分量表（内侧颞叶萎缩 MTA、全脑皮层萎缩 GCA、顶叶萎缩 Koedam 评分）来量化它们。研究文献中，仅用结构 MRI 区分 AD 与 CN 的二分类可以做到 85% 以上；但加入 MCI 的三分类要难得多，常见水平在 55%–65% 之间，因为 MCI 的萎缩程度恰好介于两者之间，信号天然重叠。

这正是这份作业“难而有趣”的原因：信息被刻意限制在 MRI + 年龄 + 性别，你无法靠堆数据取胜，只能把有限的信号用到极致。而它的前景也是真实的：一个可靠的纯 MRI 辅助评估系统，意味着任何有 MRI 设备的医院都能低成本开展早期筛查，再与快速发展的血液标志物结合。这是学界正在认真推进的方向。

Vibe Coding

让想法直接长成系统

短短几年，“AI 写代码”经历了三次跃迁。2021 年，代码补全工具让 AI 成为程序员的“输入法”；2022 年 ChatGPT 出现，人们开始用对话让 AI 写出整段程序；到 2024–2025 年，Claude Code、Cursor 这类智能体化的编程工具已经可以自主阅读整个代码库、运行测试、修复报错、循环迭代。2025 年初，Andrej Karpathy 给这种新工作方式起了个名字：vibe coding。你用自然语言描述意图，AI 负责实现，你负责品味、判断与验收。写代码的门槛，第一次从“会语法”变成了“想得清楚”。

但想得清楚，恰恰是最难的部分。Vibe coding 造一个 demo 很快，造一个严肃系统则完全是另一回事：你需要把问题拆成 AI 能够胜任的小块，为每一块设计验证方式，并诚实地评测整体效果。这些没有任何工具能替你完成。

拿我们的示例 Demo 来说，我们没有让一个大模型“看图猜病”，而是把一家医院的读片会诊流程搬进了代码里：

一份 .nii 文件进来，先由 SynthSeg 与 FreeSurfer 完成分割与量化，产出几十项脑区体积数据；影像科质控 Agent 先做质量把关，剔除不可靠的输入；影像科医生 Agent 依据数据与影像给出 MTA、GCA、Koedam 等临床量表式评分；随后初诊医生 Agent 拿着量化数据、MRI 切片图、分割图和相似典型案例，给出初步结论；质询医生 Agent 专门负责挑毛病、提出质疑；最后由定稿医生 Agent 综合各方意见，给出最终结论与一份格式化诊断报告。

每个角色都简单，链条组合起来却构成了一个有制衡、可审计的系统。而它的每一行代码，都是 vibe 出来的。我们把完整的提示词设计、迭代过程和踩过的坑都记录了下来，如果你准备开工，建议先花二十分钟读一遍。
